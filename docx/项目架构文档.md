# 项目架构文档

> 社区智能消防烟温联动监测终端 · STM32F103RCT6 标准外设库
>
> 本文是项目的**全局架构总览**。引脚细节、联动阈值、接线等局部内容见 `docx/` 下各专题文档（[第 13 节](#13-相关文档导航)），本文只给总览与导航，不重复其细节。

---

## 1. 概述

| 项 | 内容 |
|----|------|
| 定位 | 社区智能消防烟温联动监测终端：多传感器采集 → 中央引擎判报警等级 → 联动驱动风扇/水泵/蜂鸣器/灯带，LCD 菜单交互，串口调试 log |
| MCU | STM32F103RCT6（中等容量，STM32F10X_MD） |
| 库 | **STM32 标准外设库**（非 HAL/LL），路径 `~/stm32_std_lib/`（CMSIS + StdPeriph_Driver + Template） |
| 语言/工具链 | C，C17，Keil（GBK 源码，需勾选 Use MicroLIB 以支持 `printf`） |
| 架构模式 | **Superloop + 菜单驱动 + 中央联动引擎**（无 RTOS） |

核心思想：主循环每 10ms 跑一帧，**菜单框架**负责 UI 交互与视图分发，**中央引擎 alarm** 作为数据聚合中心 + 报警状态机 + 执行器调度器后台常驻。两者平级，任何菜单状态下引擎都持续运行。

## 2. 系统架构图

```
                       ┌──────────────────────────────────────┐
                       │           main.c  (Superloop)         │
                       │   joystick_event()  →  menu_handle()  │
                       │                     →  alarm_tick()    │
                       │                     →  delay_ms(10)   │
                       └─────────┬──────────────────┬───────────┘
                                 │                  │
                   ┌─────────────▼─────────┐  ┌─────▼──────────────────────┐
                   │  menu.c  菜单驱动框架  │  │  alarm.c  中央联动引擎      │
                   │  active_view 分发      │  │  采集 → 等级判定 → 执行调度 │
                   │  (菜单态 / 视图层)     │  │  (数据聚合中心)             │
                   └─────────────┬─────────┘  └──┬────────────────┬──────────┘
                                 │               │ getter         │ 联动下发
                       ┌─────────▼──────────┐    │                │
                       │   视图层 *_view     │◄───┘                │
                       │  (8 个模块视图)     │                     │
                       └─────────┬──────────┘                     │
                                 │ 数据 / 控制来源                  │
              ┌──────────────────▼────────────────────────────────▼──────────┐
              │              驱动层  (传感器  +  执行器)                       │
              │   dht · smoke · flame · light   │   fan · pump · beep · ledstrip │
              └──────────────────┬──────────────────────────────────────────────┘
                                 │ 复用统一初始化 / ADC1 共享
              ┌──────────────────▼──────────────────────────────────────────────┐
              │   平台 / 工具层   io · usart · lcd · lcd_ui · delay · sys │
              └──────────────────┬──────────────────────────────────────────────┘
                                 │
                            ┌────▼─────┐
                            │  STM32   │  硬件外设
                            └──────────┘
```

**数据流**：传感器 → alarm 聚合（节流缓存）→ 视图经 getter 显示 / 引擎按等级联动 → 执行器。

## 4. 运行模型（Superloop）

### 初始化顺序（`main.c:21-41`）

```
SysTick 配置 → USART1_init → printf("system start")
→ ui_init(LCD) → joystick_init(ADC1 + 按键)
→ smoke_init → fan_init → light_init → flame_init → pump_init → ledstrip_init → beep_init
→ alarm_init(采集+判定+调度)
→ ui_login(欢迎画面) → delay_s(2) → 清屏 → menu_init(画主菜单)
```

> 顺序约束：`joystick_init` 必须先于各 ADC 传感器 init（它初始化共享的 ADC1）；`alarm_init` 必须在所有传感器/执行器 init 之后。

### 主循环（`main.c:43-49`）

```c
while (1) {
    u8 ev = joystick_event();     // 方向事件
    u8 sw = joystick_pressed();   // 按键事件
    menu_handle(ev, sw);          // 菜单/视图分发
    alarm_tick();                 // 引擎后台常驻
    delay_ms(10);                 // 10ms 帧周期
}
```

**关键设计**：`alarm_tick()` 放在主循环顶层、与 `menu_handle` 平级——不能塞进 `menu_handle`，因为后者在视图态会 `return` 早退，而引擎必须**任何菜单状态下都持续运行**。

## 5. 菜单驱动框架（`menu.c`）

### 菜单项结构

```c
typedef struct {
    const char *text;                 // 显示文本（ASCII / GB2312 混排）
    void (*enter)(void);              // 进入视图：首次绘制
    void (*tick)(void);               // 主循环周期调用：刷新数据
    u8   (*on_event)(u8 ev, u8 sw);   // 事件处理；返回 1 = 退回主菜单
} menu_item_t;
```

### 主菜单条目（`menu_items[]`，8 项）

| # | 菜单名 | 视图回调 |
|---|--------|----------|
| 1 | 温湿度模块 | `th_view_*` |
| 2 | 烟雾报警器 | `smoke_view_*` |
| 3 | 风扇模块 | `fan_view_*` |
| 4 | 光敏模块 | `light_view_*` |
| 5 | 火焰传感器 | `flame_view_*` |
| 6 | 水泵模块 | `pump_view_*` |
| 7 | 灯带模块 | `ledstrip_view_*` |
| 8 | 蜂鸣器模块 | `beep_view_*` |

### `menu_handle(ev, sw)` 状态机

- **视图态**（`active_view != NULL`）：调 `tick()` 刷新 → `on_event(ev, sw)`，返回 1 则 `active_view = NULL` 退回主菜单并重绘。
- **菜单态**：`JOY_UP/DOWN` 循环移动 `menu_cursor`；`SW` 按下进入光标项的视图（调 `enter()`），无 `enter` 回调的占位项则置 `menu_confirmed`。

**核心卖点**：新增模块只需写一对 `xxx_view.c/.h`（三件套 enter/tick/on_event），在 `menu_items[]` 加一行——**导航框架零改动**。详见 [菜单目录构建.md](菜单目录构建.md)。

## 6. 中央引擎 alarm（架构核心）

`alarm.c/h` 是系统的"大脑"，三层职责：

### ① 数据聚合中心

- **采样节流**：ADC（smoke/flame/light）每 100ms、DHT 每 2s（`ALARM_TICK_SAMPLE=10` / `ALARM_TICK_DHT=200`，单位 10ms tick）。
- **双路融合**：火焰两路取最小（小=火，保守取危）；温湿度两路取最大（保守取热）。
- **唯一读 DHT 的地方**：避免单总线重复读取冲突；各视图经 getter 取数，不再自读。

### ② 报警等级判定（`alarm_eval_levels` → `alarm_apply_stable`）

```
单项阈值判定 (smoke/temp/rate 正向 >LN, flame 反向 <LN)
        ↓
跨模块规则合成 target_level：
   • 严重超标速判：smoke>2500 且 T>55           → L3（瞬时，跳过防误报）
   • 三项同达三级：smoke L3 ∧ temp L3 ∧ flame L3 → L3
   • 双项二级：    (smoke L2 ∧ temp L2) ∨ flame L2 → L2
   • 单项一级：    smoke L1 ∧ flame<L2           → L1
   • 否则                                          → L0
        ↓
防误报延时：L1/L2 需连续 3 次（300ms）稳定才升；L3 瞬时；target=0 立即回 0
        ↓
cur_level（生效等级）
```

### ③ 执行器调度矩阵（`alarm_dispatch_actuators`，仅 `enabled` 时）

| 等级 | fan | pump | beep | ledstrip mode |
|------|-----|------|------|---------------|
| L0 正常 | 0% | OFF | OFF | 0（灭） |
| L1 一级 | 30% | OFF | 500ms 断续 | 1（黄闪） |
| L2 二级 | 60% | OFF | 100ms 断续 | 2（橙闪） |
| L3 三级 | 100% | ON | 持续长鸣 | 3（红闪） |

- `ledstrip_set_mode` 只在等级变化时下发（避免重置 blink 计数导致不闪）。
- `ledstrip_tick()` 由 alarm 统一驱动（修复退出灯带视图后停止闪烁的 bug）。

### 控制开关与 getter

- **`alarm_enable(on)`**：1=引擎接管执行器（实战，默认）；0=只采集判定不控制（调试手动）。
- **`alarm_manual_override(mask)` / `release(mask)`**：位掩码 `ALARM_MANUAL_FAN/PUMP/LEDSTRIP/BEEP`，引擎调度时跳过被覆盖的执行器——供执行器视图实现手动操作不被引擎覆盖。
- **`alarm_mute()`**：15s 消音倒计时（L3 仍响）。
- **getter 全集**：`alarm_get_level/temp/humi/smoke/flame/light/temp_rate`（聚合值）、`_smoke/temp/flame_level`（单项等级）、`_fan_pct/pump_on`（下发值）、`_temp_n/_humi_n/_flame_n`（双路原始值，供视图显示）。阈值细节见 [功能联动文档.md](功能联动文档.md)。

### 调试 log

`alarm.c` 顶部 `#define ALARM_DEBUG_LOG`（代码内置开关），开启后每 1s 经 USART1 打印一行全模块状态：
```
[ALARM] L0 smoke=185 F1=3950 F2=3980 light=2100 T1=25 H1=40 T2=25 H2=41 rate=0 fan=0 pump=0 beep=0 led=0
```

## 7. io 基础设施（`io.c/h`）

统一外设初始化封装，各驱动复用（每次自动使能时钟）：

| 函数 | 用途 |
|------|------|
| `GPIO_init(pin_type, pin, mode, GPIOx)` | GPIO 配置（`pin_type` = `RCC_APB2Periph_TYPE_A/B/C`） |
| `EXTI_init(port_source, pin_source, line, trigger)` | 外部中断 |
| `NVIC_init(irq_channel, preemption, sub)` | 中断优先级 |
| `ADC_init(ADCx, mode, scan, cont, trig, align, nch)` | ADC 配置 |
| `TIM_base_init(TIMx, psc, arr)` / `TIM_pwm_init(TIMx, ch, pulse, polarity)` | 定时器基座 / PWM 通道 |
| `USART_init(USARTx, baud, word, stop, parity, mode)` | 串口配置 |

**ADC1 共享**：在 `joystick_init()` 中初始化为单次/软件触发/右对齐模式，所有 ADC 传感器（smoke/flame/light + 摇杆）复用，通过不同通道采集（各驱动自带 `xxx_read_adc(ch)`，4 次平均）。详见 [IO表.md](IO表.md)。

## 8. 视图层数据来源

| 视图 | AO / 数值 | DO / 状态 | 控制 |
|------|-----------|-----------|------|
| `th_view` | `alarm_get_temp_n(1/2)` · `alarm_get_humi_n(1/2)`（两路） | `alarm_get_temp_ok()` | — |
| `smoke_view` | `alarm_get_smoke()` | `smoke_read_alarm()`（硬件 DO） | — |
| `light_view` | `alarm_get_light()` | `light_read_alarm()`（硬件 DO） | — |
| `flame_view` | `alarm_get_flame_n(1/2)`（两路） | AO < 3000 软阈值 | — |
| `fan_view` | `fan_get_speed()` | — | `fan_set_speed()` |
| `pump_view` | `pump_is_on()` | — | `pump_on/off()` |
| `beep_view` | `beep_get_state()` | — | `beep_toggle()` |
| `ledstrip_view` | `ledstrip_get_mode()` | — | `ledstrip_set_mode()` |

**设计原则**：
- **传感器视图**：AO/数值走 alarm getter（数据源统一、避免 DHT 冲突）；DO 读硬件引脚（忠实反映模块电位器状态）。
- **执行器视图**：直接调驱动的 get/set。引擎 `enabled` 时全权控制执行器，视图手动操作可借 `manual_override` 协调。

## 11. 编码与约定

- **源文件编码**：`code/src/` + `code/inc/` 全部 **GB2312**（含 `io.c`，无例外；Keil 默认 GBK 兼容）。编辑含中文的源文件**禁用 sed/awk/Edit**（会损坏多字节字符），用 `.claude/tools/gb_edit.py`（按行号）或 `gb_regex_replace.py`（按正则）。`docx/` 文档用 UTF-8。
- **命名**：函数 `snake_case` + 模块前缀（`GPIO_init` / `joystick_event` / `alarm_get_level`）；宏 `UPPER_CASE`（`SMOKE_L1` / `ALARM_TICK_SAMPLE`）；ISR 共享变量 `volatile`；文件内部函数 `static`。
- **头文件保护**：`#ifndef __MODULE_H` 双下划线风格。
- **硬件抽象**：硬件宏集中在 `io.h` / 模块顶部；电平有效方向（如 `SMOKE_DO_ACTIVE_LOW`）做成可配置宏，烧录后验证。
- **注释**：用 `/* ====== 分段标题 ====== */` 划分逻辑块，中文注释。
